# Diagnostic optimization experiments

Based on main 4387f1cf62faae0171847ff7748ecef430eaabd7. Instrumentation only: no changes to the rendering algorithm, sample frequency (500 ms), two-thread architecture, USB framing, addressing, timeouts, reconnect policy, GPU/network calculations, or persistent settings. USB source is changed only to count existing API calls and bytes. A diagnostic build has extra measurement and log overhead and is not a production benchmark.

## Run

Close the stable app with Exit (same single-instance mutex). Extract the appropriate profile EXE from the CI artifact. Start it normally with the LCD connected. A timestamped lcdinfo-profile-*.log appears beside the EXE (or in %TEMP% if the directory is not writable). No extra driver, privileges, console, or configuration needed. Use the PC normally, or leave it idle for the first 2-minute measurement; preferably repeat for 15–30 minutes. Exit through the tray to obtain FINAL. Do not terminate from Task Manager unless necessary. Send the log, not a screenshot. If no log exists check %TEMP%; a log failure does not stop ordinary operation.

## Fields

Cumulative snapshots every ~10 seconds and on orderly worker exit. Startup and reconnect included; subtract two snapshots for steady-state results. All stage wall times use QPC; bracketed worker CPU uses GetThreadTimes (100 ns units, actual accounting much coarser) and QueryThreadCycleTime (cycles, not elapsed time, frequency varies). CPU/cycle valid counts must be checked. Per-stage sums are approximate and contain probe overhead; do not subtract the empty calibration blindly. CPU plus RAM, clock/uptime, network table API and remaining processing, PDH collect, formatted array (size probe, retrieval and buffer resize), GPU parsing/aggregation, render, differential encode, update and connection each have separate measurements. Connection includes initialization USB and is not a steady-state sample. GPU format calls are not samples. NetRest includes FreeMibTable; local Net destruction after scope is outside measurement. USB update counts include no-op unchanged frames. USB counters include initialization, failed calls, timeouts and successful API-returned byte counts including FTDI status bytes on reads, not physical bus overhead. Out requested includes failed transfers; successful partial writes count actual bytes and failure. Changed/unchanged count attempted frames, update_failures counts failed updates. Missing readings, table sizes and deadline overruns included.

Process/worker CPU totals from Win32, normalized process CPU percentage by active logical processors; private bytes, working set, handle count. Other OS/driver CPU outside process not measured. Process measurement starts after log creation, final snapshot before worker destruction; logging itself contributes overhead. No process names, per-engine identifiers, IP addresses or USB serials logged. Compare same workload and interval before choosing optimizations. No speedup claimed.

CI runs existing 3000-frame test and profile accounting smoke test on x86/x64; physical LCD and Windows 7 behavior still require validation. No release publication from this branch.

## Network-cache experiment

Derived from c3e34c7. The full table is read at startup and every 5 seconds, caching eligible physical Ethernet/Wi-Fi LUIDs including down interfaces. Between scans GetIfEntry2 reads each cached row every 500 ms, rechecking the original eligibility and operational status. A failed or mismatched entry causes a same-sample full scan; a failed full scan invalidates the baseline and retries next sample. No interpolation, cached traffic values, extra thread, or changed rate formula. New or newly eligible adapters can take approximately 5 seconds to be discovered; existing eligible down adapters are still sampled. Counter resets and new adapters require a new baseline as before. NetApi measures both APIs; net_total includes the entire network sample and overlaps net_api/net_rest, so do not sum it with them. net_rest now measures full-scan filtering/free only; remaining work is included in net_total. NET counts scan attempts, direct entry attempts and API errors; ITEMS net_rows/net_samples now describe successful full scans only. No measured savings yet. See Microsoft GetIfEntry2 documentation: https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getifentry2 .

## PDH-buffer experiment

Derived from network-cache. Reuse the current allocated array directly; on PDH_MORE_DATA or PDH_INVALID_ARGUMENT, issue a zero-size probe and grow if necessary, with at most three retrieval attempts and a 32 MiB limit. The size returned for a nonzero short buffer is not reliable according to Microsoft. Keep the buffer on shrink and preserve missing-data behavior on other errors. Same counter query, collection cadence, format flags, parsing and result. GPU format counts now normally one API call per sample; occasional extra calls on buffer growth. Allocation/resizing now outside the GPU format scope; process totals still include it. No assumption that eliminating one call halves CPU. Docs: https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhgetformattedcounterarrayw .
